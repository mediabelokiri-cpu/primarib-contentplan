## PRIMA RIB CONTENT PLAN
### AI-Powered Content Management & Production Platform

**Document Version:** 1.0  
**Database Specification:** Target Logical ERD  
**Development Environment:** Antigravity  
**Status:** Provisional — Requires Existing Database Audit

---

# 1. DATABASE DESIGN OBJECTIVES

Database dirancang untuk mendukung pengembangan Prima RIB Content Plan menjadi AI-powered content management platform.

Tujuan:

1. Menyimpan identitas dan pengetahuan brand.
2. Menyediakan sumber pengetahuan terstruktur untuk AI.
3. Mendukung berbagai provider dan model AI.
4. Mendukung AI orchestration dan task routing.
5. Menyimpan hasil AI Content Strategist.
6. Menyimpan script dan version history.
7. Menyimpan creative brief.
8. Menyimpan hasil quality check.
9. Menyimpan usage, cost, error, dan feedback.
10. Terintegrasi dengan database content management existing.

## 1.1 Critical Database Rule

ERD ini merupakan logical target model, bukan instruksi untuk langsung membuat seluruh tabel.

Sebelum migration:
- Audit semua tabel existing.
- Identifikasi entitas yang sudah tersedia.
- Gunakan tabel existing apabila fungsinya sudah sesuai.
- Tambahkan kolom apabila lebih aman daripada membuat tabel duplikat.
- Hindari duplicate content entities.
- Pertahankan seluruh data dan relasi existing.

Nama tabel dan kolom existing harus menjadi acuan final physical ERD.

# 14. DATABASE CONSTRAINTS

Ketentuan:

1. Semua primary key baru menggunakan UUID, kecuali database existing menggunakan standar lain yang harus dipertahankan.
2. Foreign key harus memiliki referential integrity.
3. Field wajib harus memiliki NOT NULL.
4. Field unik harus memiliki UNIQUE constraint.
5. Status harus menggunakan nilai yang tervalidasi.
6. Tanggal menggunakan timezone-aware timestamp jika didukung.
7. Harga menggunakan NUMERIC, bukan floating point.
8. Metadata fleksibel dapat menggunakan JSONB jika database mendukung.
9. Index ditambahkan pada foreign keys dan kolom pencarian yang sering digunakan.
10. Soft delete hanya diterapkan jika sesuai dengan pola database existing.
11. Riwayat versi script tidak boleh tertimpa.
12. Penghapusan data harus mempertimbangkan relasi dan audit trail.

## Phase 2 — Migration Design

Buat migration secara incremental.

Ketentuan:
- Tidak boleh DROP existing tables.
- Tidak boleh TRUNCATE existing tables.
- Tidak boleh reset production database.
- Tidak boleh mengubah primary key existing tanpa justifikasi dan approval.
- Tidak boleh menghapus existing relationships.
- Semua perubahan harus terdokumentasi.
- Migration harus dapat diuji di environment development terlebih dahulu.

## Phase 3 — Migration Testing

Uji:
- Migration up.
- Migration rollback jika memungkinkan.
- Foreign key integrity.
- Existing data integrity.
- RLS policies.
- Authentication.
- Existing application workflows.

## Phase 4 — Deployment

Sebelum production:
- Backup database.
- Review migration.
- Jalankan staging test.
- Verifikasi data.
- Siapkan rollback procedure.
