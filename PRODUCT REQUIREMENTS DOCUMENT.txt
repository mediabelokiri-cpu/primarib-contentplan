# 1. PRODUCT OVERVIEW

## 1.1 Product Description

Prima RIB Content Plan merupakan platform manajemen konten dan produksi konten digital untuk brand Prima RIB.

Aplikasi yang saat ini berfungsi sebagai sistem perencanaan konten manual akan dikembangkan menjadi AI-Powered Content Management & Production Platform.

Sistem akan mengintegrasikan kecerdasan buatan untuk membantu proses:

1. Pengelolaan identitas dan pengetahuan brand.
2. Perencanaan strategi konten.
3. Pengembangan ide konten.
4. Penulisan script dan copywriting.
5. Pembuatan creative brief.
6. Pemeriksaan kualitas konten.
7. Pengelolaan produksi dan persetujuan konten.
8. Evaluasi dan pengembangan strategi konten.

AI harus memahami karakteristik, produk, layanan, audiens, gaya komunikasi, dan tujuan pemasaran Prima RIB berdasarkan data pengetahuan brand yang dikelola secara terpusat.

## 1.2 Product Vision

Menjadi platform manajemen dan produksi konten berbasis AI yang mampu membantu tim Prima RIB menghasilkan konten secara lebih strategis, konsisten, efisien, dan berkualitas.

## 1.3 Product Mission

- Memusatkan seluruh aktivitas perencanaan dan produksi konten.
- Mengintegrasikan brand knowledge ke dalam proses kerja AI.
- Mempercepat pengembangan ide dan penulisan script.
- Menjaga konsistensi komunikasi brand.
- Mengurangi pekerjaan repetitif dalam produksi konten.
- Mempertahankan kontrol kreatif dan keputusan akhir pada manusia.

## 1.4 Product Positioning

AI-powered internal content management platform untuk kebutuhan pemasaran dan komunikasi brand Prima RIB.

---

# 2. PRODUCT DEVELOPMENT PRINCIPLES

Pengembangan wajib mengikuti prinsip berikut:

1. Single Brand: sistem hanya digunakan untuk Prima RIB.
2. Hybrid AI: mendukung beberapa provider AI melalui arsitektur terpusat.
3. Script-Based Production: AI menghasilkan ide, script, copywriting, dan creative brief, bukan gambar atau video.
4. Human-in-the-Loop: seluruh keputusan dan persetujuan akhir tetap dilakukan manusia.
5. Backward Compatibility: seluruh fitur dan data aplikasi existing harus tetap berfungsi.
6. Incremental Development: pengembangan dilakukan bertahap.
7. Data Integrity: tidak boleh menghapus, mereset, atau merusak data existing.
8. Extensible Architecture: provider, model, prompt, dan modul AI dapat dikembangkan tanpa membangun ulang sistem.

- Content Version Management.
- Existing Production Board Integration.
- Existing Content Calendar Integration.
- Reporting and Analytics Integration.

## 3.2 Out of Scope

Untuk versi ini, sistem tidak mencakup:

- AI image generation.
- AI video generation.
- AI voice generation.
- Automatic social media publishing.
- Automatic advertisement deployment.
- Multi-brand management.
- Autonomous content approval.
- Autonomous marketing decisions.
- Automatic claims about current CPNS, Sekdin, or Polri regulations without verified sources.

# 5. EXISTING SYSTEM PRESERVATION

Sebelum implementasi, lakukan audit menyeluruh terhadap:

- Struktur aplikasi dan routing.
- Seluruh halaman dan komponen.
- Database schema.
- Authentication.
- User roles dan permissions.
- Content Planner.
- Idea Bank.
- Production Board.
- Content Calendar.
- Review and Approval.
- Published Content.
- Reporting.
- Existing API dan integrations.

Ketentuan:

1. Jangan membangun ulang aplikasi.
2. Jangan mengganti framework tanpa alasan teknis yang kuat.
3. Jangan menghapus fitur existing.
4. Jangan mengganti desain existing secara menyeluruh.
5. Jangan menghapus atau mereset tabel database.
6. Jangan mengganti struktur data existing tanpa migration plan.
7. Pertahankan seluruh workflow manual.
8. Tambahkan workflow AI sebagai pilihan baru.

Sistem harus mendukung dua metode produksi:

- Manual Content Creation.
- AI-Assisted Content Creation.

Keduanya harus terintegrasi ke workflow konten yang sama.

## MODULE 02 — HYBRID AI INFRASTRUCTURE

### Tujuan

Membangun arsitektur AI terpusat yang mendukung beberapa provider dan model.

### FR-013 AI Provider Management

Mendukung provider yang dapat dikonfigurasi, dengan kandidat awal:
- OpenAI.
- Google Gemini.
- Anthropic Claude.

Provider tambahan harus dapat diintegrasikan melalui adapter.

### FR-014 Provider Credentials

Admin dapat mengatur API credentials.

Ketentuan keamanan:
- Credentials disimpan secara aman di server.
- Tidak boleh dikirim ke browser.
- Tidak boleh ditampilkan dalam plaintext setelah disimpan.
- Tidak boleh masuk ke client-side logs.
- Mendukung rotasi credentials.

### FR-015 Model Management

Admin dapat:
- Menambahkan model.
- Mengaktifkan atau menonaktifkan model.
- Menentukan default model.
- Menentukan model untuk task tertentu.
- Mengatur model fallback.
- Mengatur parameter yang didukung provider.

### FR-016 AI Task Routing

Sistem dapat menentukan model berdasarkan jenis pekerjaan.

Contoh:
- Content Strategy.
- Idea Generation.
- Script Writing.
- Copywriting.
- Creative Brief.
- Content Quality Check.
- Text Analysis.

### FR-017 Manual Model Override

User yang memiliki permission dapat memilih provider/model untuk proses tertentu jika diizinkan Admin.

### FR-018 Automatic Fallback

Jika provider utama gagal, sistem dapat mencoba provider alternatif yang telah dikonfigurasi.

Fallback harus:
- Mencatat kegagalan provider awal.
- Mencatat provider pengganti.
- Mempertahankan konteks request.
- Tidak menghasilkan konten duplikat tanpa alasan.
- Menghentikan retry berlebihan.

### FR-019 AI Orchestration

Seluruh request AI diproses melalui satu lapisan orchestration.

Lapisan ini bertanggung jawab atas:
- Authentication.
- Permission validation.
- Context preparation.
- Knowledge retrieval.
- Prompt assembly.
- Model routing.
- Request execution.
- Output validation.
- Usage logging.
- Error handling.

### FR-020 Context Injection

Setiap AI request yang membutuhkan pemahaman brand harus menerima konteks relevan dari Brand Studio.

### FR-021 Prompt Assembly

Prompt dibangun dari:
- System instruction.
- Brand context.
- Task instruction.
- User input.
- Retrieved knowledge.
- Output schema.

### FR-022 Structured Output

Output AI harus divalidasi sesuai format yang diminta.

Jika output tidak valid, sistem dapat melakukan perbaikan terbatas atau meminta regenerasi.

### FR-023 Request Status

Setiap request memiliki status:
- Pending.
- Processing.
- Completed.
- Failed.
- Cancelled.

### FR-024 Usage Logging

Mencatat:

- Provider.
- Model.
- Task type.
- Token usage jika tersedia.
- Estimated cost jika tersedia.
- Duration.
- Request status.
- Error details.
- Timestamp.

### FR-025 Usage Limits

Admin dapat mengatur batas penggunaan AI berdasarkan kemampuan provider dan arsitektur sistem.

- AI requests mendukung asynchronous processing bila diperlukan.
- UI tidak boleh freeze selama proses AI.
- Loading state harus jelas.
- Request timeout dan retry harus dikonfigurasi.
- Target performa frontend ditentukan melalui pengujian aplikasi existing.

## Reliability
- Provider failure handling.
- Fallback mechanism.
- Error logging.
- Retry limits.
- Request cancellation jika didukung.

## Scalability
- Provider adapter architecture.
- Modular AI task routing.
- Extensible prompt management.
- Database indexing sesuai kebutuhan.

## Maintainability
- Modular components.
- Reusable services.
- Clear API contracts.
- Migration documentation.
- Technical documentation.

# 11. AI SAFETY AND CONTENT GOVERNANCE

AI tidak boleh:
- Mengarang harga produk.
- Mengarang promo.
- Mengarang jadwal pendaftaran.
- Mengarang passing grade.
- Mengarang syarat seleksi.
